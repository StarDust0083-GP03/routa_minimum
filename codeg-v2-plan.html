codeg v2 — Implementation Plan

Sub-Task Architecture · ACP Protocol Rework · Two-Phase Agent Workflow

Problem 1

ACP Integration Uses Wrong Transport

Currently spawns opencode run as a one-shot subprocess. This is a fire-and-forget pattern — no session management, no resume, no multi-turn interaction.

Must use: opencode serve as a persistent ACP server, communicating via JSON-RPC 2.0 + SSE — the actual ACP protocol.

Fix

Full ACP Lifecycle via JSON-RPC + SSE

  • POST /api/acp — initialize, session/new, session/prompt, session/cancel
  • GET /api/acp?sessionId=xxx — SSE streaming updates
  • Session persistence, resume, cancel
  • Proper session/update event handling
Problem 2

Flat Task Model — No Decomposition

Tasks are monolithic: one directory, one agent. No way to split work across directories or coordinate multiple agents.

Missing: sub-tasks, planning workflow, per-directory agents, verification phase.

Fix

Task → SubTask → Two-Phase Agent Execution

  • Each Task has N SubTasks, each in its own directory
  • Plan mode: LLM-assisted decomposition with user confirmation
  • Two phases per SubTask: Coding (DEVELOPER) + Verification (GATE)
  • Each phase = one ACP session from the sub-task's directory

SubTask Model

type SubTaskStatus string
const (
    SubTaskPlanned    SubTaskStatus = "planned"
    SubTaskCoding     SubTaskStatus = "coding"
    SubTaskVerifying  SubTaskStatus = "verifying"
    SubTaskDone       SubTaskStatus = "done"
    SubTaskFailed     SubTaskStatus = "failed"
)

type SubTask struct {
    ID                   string        `json:"id"`
    TaskID               string        `json:"taskId"`
    Title                string        `json:"title"`
    Description          string        `json:"description"`
    Directory            string        `json:"directory"`
    Status               SubTaskStatus `json:"status"`
    OrderIndex           int           `json:"orderIndex"`
    CodingSessionID      string        `json:"codingSessionId,omitempty"`

3. ACP Session Lifecycle

sequenceDiagram
    participant C as codeg TUI
    participant M as AcpManager
    participant S as opencode serve
    participant A as Agent Process

    Note over C,A: Phase 1 — Coding (role: DEVELOPER)

    C->>M: StartSubTask(subTask, phase="coding")
    M->>S: POST /api/acp {"method":"initialize"}
    S-->>M: {"protocolVersion":1}
    M->>S: POST /api/acp {"method":"session/new","params":{"cwd":"/project/backend",...}}
    S->>A: Spawn agent in /project/backend
    S-->>M: {"sessionId":"ses_abc123"}
    M->>M: Store codingSessionID on SubTask
    M->>S: POST /api/acp {"method":"session/prompt","params":{"prompt":"Implement auth..."}}
    S-->>A: Forward prompt
    M->>S: GET /api/acp?sessionId=ses_abc123 (SSE)
    loop Streaming
        S-->>M: event: agent_message_chunk
        M-->>C: AgentEventMsg → agentPanel
        S-->>M: event: tool_call
        S-->>M: event: tool_call_update
    end
    S-->>M: event: turn_complete
    M->>C: Phase complete

    Note over C,A: Phase 2 — Verification (role: GATE)

    C->>M: TransitionPhase(subTask, phase="verifying")
    M->>S: POST /api/acp {"method":"session/new","params":{"cwd":"/project/backend","role":"GATE"}}
    S->>A: Spawn verification agent
    S-->>M: {"sessionId":"ses_def456"}
    M->>M: Store verificationSessionID on SubTask
    M->>S: POST /api/acp {"method":"session/prompt","params":{"prompt":"Verify the auth implementation..."}}
    M->>S: GET /api/acp?sessionId=ses_def456 (SSE)
    loop Verification
        S-->>M: event: agent_message_chunk
        M-->>C: Verification messages → agentPanel
    end
    S-->>M: event: turn_complete
    M->>C: SubTask done

Manual Checklist

  1. Launch TUI → empty task list
  2. Create task → enter plan mode (p) → LLM suggests sub-tasks → confirm
  3. Sub-tasks appear in tree under task with planned status
  4. Select sub-task → press r → coding phase starts → ACP session created in sub-task directory
  5. Agent output streams in real-time in the bottom panel
  6. Coding completes → auto-transitions to verification phase
  7. Verification agent checks work → shows results → sub-task marked done
  8. Next sub-task auto-starts (or press r)
  9. All sub-tasks done → task marked complete → summary generated

9. Risks & Mitigations

RiskMitigation
opencode serve crashes mid-sessionAcpManager monitors child process health; auto-restarts server; sessions persist in SQLite for resume
Verification agent finds no issues (false positive)GATE prompts include specific checks: "verify every file mentioned in the coding session, run tests, check for edge cases"
Sub-tasks have dependencies (ordering)OrderIndex enforces sequential execution; dependency graph can be added later
LLM produces bad sub-task decompositionPlan mode is interactive — user can edit, add, remove, reorder sub-tasks before confirming
ACP server port conflictsUse random port (port 0) and read actual port from server log output
