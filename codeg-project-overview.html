Three Core Capabilities

1. Task Management

Persistent task store backed by SQLite with full CRUD, status lifecycle, priority levels, labels, and bound directories.

  • Task.SessionIDs — links agent sessions to tasks
  • Task.BoundDirs — multi-directory binding
  • CompleteTask() → OpenAI summary generation
  • Status lifecycle: pending → in_progress → review → completed

2. Directory-Bound Coding Agents

Each task binds multiple directories. The TUI spawns AI coding agents in those directories via two interchangeable backends:

  • OpenCode runner — spawns opencode run subprocess
  • ACP runner — JSON-RPC 2.0 over HTTP with SSE streaming
  • Session IDs captured and linked to tasks
  • Cancel support via process kill or RPC cancel

3. Progress Dashboard

Real-time Bubble Tea TUI showing all tasks and live agent output in a three-panel split layout.

  • Left: selectable task list with status-colored dots
  • Right: task detail (objective, dirs, sessions, summary)
  • Bottom: real-time agent output via agentEvents channel
  • Status bar with live task/agent counts

How to Run

cd ~/Documents/code/coding-agent

# Optional: set OpenAI key for task summaries
export OPENAI_API_KEY="sk-..."

# Optional: point to ACP server
export CODEG_ACP_URL="http://localhost:3000/api/acp"

# Build and run
go build -o bin/codeg ./cmd/codeg
./bin/codeg

# Or with debug logging
./bin/codeg --debug

The TUI works standalone for task management without any external services. Pressing r on a task with bound directories spawns opencode (must be installed; uses its own provider config at ~/.local/share/opencode/auth.json). Task summaries require OPENAI_API_KEY. ACP server is optional — the default backend is the opencode subprocess runner.
